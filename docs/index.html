Big data notes

Lab notes on Hadoop, Hive, MongoDB and Android intents, made searchable, with a word-count job you can step through.

The six .txt files in the repository are embedded here word for word. This page runs entirely in your browser and makes no network requests.
01 · Reference

Notes explorer

Six text files, split into small labelled parts with a plain explanation beside each. Parts marked Check contain something that is wrong, misleading or cannot be run as written.

What the files are

Course-lab notes: an HDFS shell session, a Java word-count job, HiveQL, MongoDB shell commands, and two small Android apps about intents.

The swapped Android names

explicit.txt dials with Intent.ACTION_DIAL and no class name, which is an implicit intent. implicit.txt starts MainActivity2.class by name, which is an explicit intent.

Reading the Check badges

They come from reading the code against the language or tool, not from running it. Hive, MongoDB and Hadoop are not installed here, so none of the original commands were executed.

02 · MapReduce

Word count, step by step

The job from WordCount.txt, run in your browser: map each word to (word, 1), optionally combine per mapper, shuffle and sort by key, then reduce by summing. Edit the text and watch every stage change.

Input

The notes' sample is rebuilt from the recorded output, because the real gg.txt is not in the repository.

Matches WordCount.txt

What it does

Counts how often each word appears. Map turns each word into a (word, 1) pair, the framework groups pairs by word, and reduce adds up each group.

How this repo does it

Wordcount.Map uses StringTokenizer (splits on space, tab, newline, carriage return, form feed); Wordcount.Reduce sums the counts and is also the combiner. This page applies those same rules and sorts keys by their UTF-8 bytes, as Hadoop's Text does.

How to read it

With the combiner on, each mapper first adds up its own words, so fewer pairs cross the network: compare "Words emitted" with "Pairs shuffled". The final counts are the same either way.

Honest note. This is a simulation of the algorithm, not Hadoop. The notes' job read one small file, which Hadoop runs as a single mapper; the mapper selector splits the lines evenly only to show how a combiner works. Java and Hadoop are not installed on the machine used to build this page, so Wordcount.java itself was not run. The page's counts were checked against an independent Python implementation of the same rules.

What it does
Takes each command from mongodb.txt or Hive.txt, runs it on the rows the notes themselves insert, and shows the result next to the command text.

    
How the page does it
Each preset is hand-written JavaScript for that one query (filtering, grouping, averaging). The custom filter box uses a small matcher for the operators listed. Updates and deletes change the table above until you press Reset.

    
How to read it
The notes list queries before the data is inserted, so the results here are what they would return after the insert. Commands marked in the Notes tab as broken (GROUP_CONCAT, MAX without GROUP BY, the Sta map-reduce) show why instead of a result.
